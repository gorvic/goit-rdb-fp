## Нормалізація до 3NF

У вихідній таблиці `entity` та `code` повторюються для кожного року спостереження.

Оскільки в межах набору даних виконується залежність:

```text
entity → code
```

довідкові атрибути території винесено в окрему таблицю:

```text
pandemic.entities
```

Річні показники зберігаються в:

```text
pandemic.infectious_cases_normalized
```

Для зв’язку використовується `entity_id`, а складеним первинним ключем є:

```text
(entity_id, year)
```

Після нормалізації:

- кількість записів залишилася незмінною — **10 521**;
- записів без відповідної території не виявлено;
- двостороння перевірка через `EXCEPT` дала `mismatched_rows = 0`.

## Аналіз `number_rabies`

Для кожної території розраховано:

- середнє значення;
- мінімальне значення;
- максимальне значення;
- суму.

Результат відсортовано за середнім значенням у порядку спадання та обмежено першими 10 рядками.

У верхній частині результату переважають світові й регіональні агрегати, тому отриману першу десятку не слід трактувати як рейтинг лише окремих країн.

## Робота з датами

Для перетворення числового року на дату використовується:

```sql
MAKE_DATE(year, 1, 1)
```

Різниця до поточної дати обчислюється через:

```sql
AGE(CURRENT_DATE, ...)
```

із подальшим отриманням кількості повних років.

## SQL-функції

У проєкті створено дві власні функції.

### `years_since()`

Приймає рік і повертає кількість повних років від першого січня цього року до `CURRENT_DATE`.

Функція визначена як `STABLE`, оскільки залежить від поточної дати.

### `avg_cases_per_period()`

Приймає річне числове значення та кількість періодів у році.

Використані дільники:

- `12` — середнє за місяць;
- `4` — середнє за квартал;
- `2` — середнє за півріччя.

Функція визначена як `IMMUTABLE`, оскільки результат залежить лише від переданих аргументів.

Отримані значення є умовним середнім при рівномірному розподілі річного показника, а не фактичними даними за коротші періоди.
